# /hilfe Implementation Plan (Plan 45, W-0014 Teil 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Befehl `/hilfe`, der in einer ephemeren Nachricht alle Befehle des Bots erklärt: Startseite B, Bereichsseite C, Befehlsseite A, Befehlsgruppe K.

**Architecture:** Die Hilfetexte stehen von Hand geschrieben in einem Katalog (`constants/HelpCatalog.ts`). Ein reines Modell (`services/help/HelpModel.ts`) verbindet Katalog und die echten Befehlsdefinitionen (Felder, Pflicht, Auswahl kommen immer aus `command.data.toJSON()`), eine Prüfung meldet fehlende oder falsche Texte. Reine View-Funktionen (`builder/HelpView.ts`) bauen daraus Components-V2-Nachrichten; der Befehl und ein Event für `hilfe:`-Knöpfe und -Menüs tauschen den Inhalt derselben Nachricht.

**Tech Stack:** TypeScript, discord.js v14 Components V2 (`ComponentV2Builder`), `@napi-rs/canvas` für das Banner, Prüfungen als `src/scripts/Check*.ts`.

**Spec:** `Admin Dashboard/docs/superpowers/specs/2026-11-01-hilfe-befehl-design.md`

## Global Constraints

- Alles ephemeral; Menüs und Knöpfe ändern dieselbe Nachricht (`interaction.update`), keine neuen Nachrichten.
- Keine Pings: jede Antwort `allowedMentions: { parse: [] }`.
- Developer-Befehle (`developerOnly`) sieht nur, wer in `config.DEV_USER_IDs` steht.
- Felder kommen nur aus der Befehlsdefinition; der Katalog beschreibt sie, erfindet keine.
- Bereiche und Reihenfolge: Immer dabei, Rocket League, Community, Support, Moderation, Inhalte & Meldungen, dazu „Allgemein“ für Befehle ohne Modul. Leere Bereiche erscheinen nicht.
- Links: Status `https://status.nexus-emb.de`, Support `https://discord.gg/CjG2HFGw95`, Doku `${SITE_PUBLIC_URL}`-unabhängig über das Dashboard: `${client.server.BaseURL}/dashboard/docu.html#docg-<bereich>`, Dashboard `${client.server.BaseURL}/dashboard/guild/<guildId>/<modul>`.
- Befehle eines Moduls, das auf dem Server aus ist: bleiben drin, mit „Modul aus“ und dem Hinweis auf `/module an` oder das Dashboard.
- Texte: Deutsch, du-Form, natürlich, keine Gedankenstriche als Stilmittel, nur was der Befehl wirklich tut.
- `/hilfe` gehört zu keinem Modul (`module: null`), `setContexts(InteractionContextType.Guild)`.
- Prüfen im Dev Server nur in der Kategorie „Claude“ mit dem Development-Bot.

## Review Focus

1. Eine Befehlsseite länger als 4000 Zeichen (etwa /giveaway, /backup): Der Builder kürzt sonst still mit „…“. Erwartet: Seiten werden geteilt, nichts fehlt. Test in Task 3.
2. Mehr als 25 Befehle in einem Bereich oder als Vorschläge: Discord nimmt höchstens 25 Einträge in Menü und Autocomplete. Erwartet: abgeschnitten auf 25, kein Fehler. Test in Task 3 und 5.
3. `/hilfe befehl:` mit Unsinn oder einem Developer-Befehl als Nicht-Developer: Erwartet: freundliche Meldung „Den Befehl gibt es nicht“ statt Fehler oder Leck. Test in Task 5.
4. Ein Knopf einer alten Hilfe-Nachricht nach einem Neustart, oder zu einem Befehl, den es nicht mehr gibt: Erwartet: zurück zur Startseite statt Fehler. Test in Task 5.
5. Server ohne Datenbank oder Bezahlschranke aus: Kachel „Zugang“ zeigt „Frei“ oder „–“, nichts bricht. Test in Task 5.
