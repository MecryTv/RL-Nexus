# W-0057 Dauerhafte Sperre mit VPN-Erkennung – Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Das Team sperrt Personen dauerhaft in fünf Bausteinen; Bot, Bot-Dashboard, Webseite und Shop halten sich daran; Anmeldungen werden auf Umgehung geprüft (gleiche IP, VPN über Proxycheck).

**Architecture:** Sperren, Prüfung und Proxycheck liegen im Admin Dashboard (`server/security/*`, Migration 019). Der Bot hält die Sperrliste im Speicher, prüft jede Interaktion vor allen Handlern und fragt bei Anmeldungen ins Bot-Dashboard das Admin Dashboard (`/internal/security/check`). Webseite und Shop prüfen im Shop-Callback.

**Tech Stack:** Fastify, MariaDB, React 19, discord.js 14, `@napi-rs/canvas`, Proxycheck v2 API.

**Spec:** `Admin Dashboard/docs/superpowers/specs/2026-11-01-admin-dashboard-design.md`, Teil 4.

## Global Constraints

- Bausteine: `others` (Bot auf fremden Servern), `own` (Eigene Server), `dashboard`, `website`, `shop`. Voll = alle, Nur Besitz = own, dashboard, shop.
- IP nie im Klartext (Datenbank, Log, Protokoll); HMAC-SHA256 mit `IP_HASH_SECRET`, sonst aus `SERVER_JWT_SECRET` abgeleitet; Netz IPv4 /24, IPv6 /48.
- Ohne `PROXYCHECK_API_KEY` oder ohne Antwort in 3 Sekunden: niemand blockiert, nur protokolliert.
- Anmeldespuren 90 Tage, außer sie hängen an einer Sperre oder einem offenen Verdacht.
- Team (Administrator, Developer) lässt sich nicht sperren. Sperren, ändern, aufheben: Admin und Developer, alles im Protokoll.
- Eine DM je Sperre oder Änderung (Bild, Entwurf vorher zeigen), danach keine Antwort vom Bot auf gesperrten Bausteinen.
- Commits ohne Co-Authored-By, nur gezielt `git add`, nie die `.env`.

## Review Focus

1. Teilsperre sperrt mehr als ihre Bausteine (etwa Nur Besitz blockiert den Bot auf fremden Servern).
2. Proxycheck fehlt, ist langsam oder antwortet mit Fehler: niemand bleibt draußen.
3. Moderation gegen eine gesperrte Person (Automod, Fälle, Befehle anderer) wirkt weiter.
4. IP taucht in Log, Fehlertext oder Protokoll auf.
5. Sperrliste im Bot veraltet (Admin nicht erreichbar): spätestens nach 5 Minuten aktuell.

---

### Task 1: Daten und Regeln (Admin)
Migration `019_security.sql` (`security_bans`, `security_ban_changes`, `security_evidence`, `security_logins`, `security_suspects`, `server_blocks.origin`), `shared/security.ts` (Bausteine, Vorlagen, `scopeOf(preset)`, `blocks(ban, service)`, Listen „Gesperrt“/„Weiter nutzbar“), `server/security/store.ts`, Datenschutz-Verzeichnis (Bereich Sicherheit, Vorgabe bleibt, Berechtigtes Interesse), Backups-Ausnahmen. Tests in `server/checks/security.check.ts`.

### Task 2: Prüfung bei der Anmeldung (Admin)
`server/security/hash.ts` (HMAC, Netz), `server/security/proxycheck.ts` (3 s, ohne Key null), `server/security/check.ts` (`decideLogin`: Sperre, gleiche IP, VPN mit jungem Konto oder Netz eines Gesperrten), Einbau im Shop-Callback, `/internal/security/check` für den Bot, Uhr löscht Spuren nach 90 Tagen. Tests mit nachgestelltem Proxycheck.

### Task 3: Sperren, ändern, aufheben (Admin)
`server/security/flow.ts` (sperren mit verknüpften Konten, ändern, aufheben, „Bot verlässt“ über `server_blocks`, Bescheid an den Bot), DM-Bild C2 (nach Freigabe des Entwurfs), Belege (Upload und Discord-Links über den Bot), Routen `/api/security/*`. DB-Test.

### Task 4: Bot
Sperrliste im Speicher (Start, `/dcapi/admin/security/reload`, alle 5 Minuten), Prüfstelle vor allen Handlern für Interaktionen, Gesperrte nie Ansprechpartner und kein Freigabe-Pass (W-0064), eigene Server ohne Besitzerrechte im Bot-Dashboard, Anmeldung ins Bot-Dashboard mit Prüfung D3 und Sperrseite C4c, Belege holen (`/dcapi/admin/security/message`). Check `CheckSecurity.ts`.

### Task 5: Oberfläche im Admin
Bereich „Sicherheit“ in der Leiste mit Zahl offener Verdachtsfälle, Seiten Sperren (Liste, Profil mit Reitern Server, Belege, Treffer, Protokoll), Verdacht, VPN-Prüfung (mit Testabfrage), Sperrfenster B1a V1 (auch für Ändern und Aufheben).

### Task 6: Webseite
Sperrseite C4c und „Anmeldung über VPN nicht möglich“ (nach Freigabe des Entwurfs) auf Zugang und Preise, Abschnitt in der Datenschutzerklärung (Text vorher zeigen).

### Task 7: Abschluss
Alle Checks, Abschluss-Review, Merge, Push, Deploy. Der Nutzer setzt `PROXYCHECK_API_KEY` (und optional `IP_HASH_SECRET`) selbst in die `.env` des Admin Dashboards.
