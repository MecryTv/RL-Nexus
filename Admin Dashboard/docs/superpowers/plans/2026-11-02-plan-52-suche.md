# Suche findet alles (W-0059) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Das Suchfenster der Leiste findet neben Seiten auch Personen, Server, Mails, Inhalte und Einträge aus Protokoll und Meldungen, in der Variante SC (Filter oben, eine Liste).

**Architecture:** Gemeinsame Typen, Falten und Rangfolge in `shared/search.ts`. Der Server beantwortet `GET /api/search` mit einer Antwort: Er fragt alle Quellen gleichzeitig, jede mit 2 Sekunden Zeit, und führt Personen über die Discord-ID zusammen. Seiten sucht weiter der Browser. Das Fenster mischt beides, filtert und markiert.

**Tech Stack:** React 19, react-router-dom, SCSS-Module, Fastify, MariaDB (`query`), IMAP über `server/mail/mailbox.ts`, Prüfungen ohne Framework (`npm run check`, `npm run check:db`).

**Spec:** `Admin Dashboard/docs/superpowers/specs/2026-11-01-admin-dashboard-design.md`, Teil 5 und Entscheidungen 20 bis 31. Entwurf: `.works/tasks/W-0059-…/design/SAtoSC-…html`, Variante SC.

## Global Constraints

- Node lädt TypeScript im Strip-only-Modus: Importe mit Endung `.ts`, keine Parameter-Properties, keine Enums.
- Keine neue Abhängigkeit.
- Alle Texte auf Deutsch, ohne Floskeln. Filter heißen genau: Alles, Seiten, Personen, Server, Mails, Inhalte, Protokoll.
- Kürzel: `@` Personen, `#` Server, `/` Seiten.
- Grenzen: Server-Suche ab **2 Zeichen**, Anfrage **200 ms** nach dem letzten Tastendruck, **2 Sekunden** je Quelle, **20 Treffer je Filter** (sonst „20+“), **40 Zeilen** in „Alles“.
- Protokoll des Admin Dashboards (`admin_audit`) nur für die Rolle `developer`.
- Volle Kunden-Mail nie im Treffer; im Kontext `maskEmail` aus `shared/shop.ts`.
- Die Suche schreibt nichts und legt keine Protokollzeile an.
- Commits unter dem Account des Nutzers, ohne Co-Authored-By, `.env` nie stagen.

## Review Focus

1. Ein Admin bekommt über `GET /api/search` Zeilen aus `admin_audit`. Erwartet: nie, auch nicht mit `art=protokoll`.
2. Eine hängende Quelle (IMAP ohne Antwort) hält die Antwort länger als 2 Sekunden auf. Erwartet: Antwort nach höchstens etwa 2 s, Quelle in `failed`.
3. Eingabe mit `%`, `_` oder `\` („100%“) findet in SQL-Quellen alles. Erwartet: wörtlich gesucht.
4. Eine ältere, langsame Antwort kommt nach einer neueren an und überschreibt sie. Erwartet: abgebrochen, die Liste passt zur aktuellen Eingabe.
5. Nur ein Kürzel oder ein Zeichen („@“, „#a“): Erwartet keine Anfrage, nur der Hinweis bzw. die Seiten.

Zeilen 1 bis 3 haben einen Test in Task 2 bzw. 3. Zeilen 4 und 5 liegen im React-Hook `useSearch`, den `npm run check` nicht laden kann: 5 ist über `parseQuery` und `SEARCH_MIN` getestet, 4 prüft Task 6 im Browser (schnell tippen, Netzwerk-Reiter zeigt abgebrochene Anfragen).

**Files:**

**Interfaces:**
- Produces:
  - `SEARCH_KINDS = ["seiten", "personen", "server", "mails", "inhalte", "protokoll"] as const`, `type SearchKind`, `SEARCH_LABELS: Record<SearchKind, string>`
  - `SEARCH_MIN = 2`, `SEARCH_DEBOUNCE_MS = 200`, `SEARCH_TIMEOUT_MS = 2000`, `SEARCH_PER_KIND = 20`, `SEARCH_ALL = 40`
  - `interface ISearchHit { kind: SearchKind; icon: string; title: string; place: string; context: string; href: string; at: string | null; rank: number }`
  - `interface ISearchResult { hits: readonly ISearchHit[]; counts: Partial<Record<SearchKind, number>>; capped: readonly SearchKind[]; failed: readonly SearchKind[] }`
  - `fold(text: string): string` (bisher in `src/nav/search.ts`)
  - `rankOf(title: string, context: string, query: string): number | null` – `query` schon gefaltet; 0 Titel beginnt damit oder ein Wort darin, 1 Titel enthält es, 2 Kontext enthält es, sonst null
  - `parseQuery(input: string): { kind: SearchKind | null; text: string }` – Kürzel am Anfang, `text` getrimmt ohne Kürzel
  - `sortHits(hits: readonly ISearchHit[]): ISearchHit[]` – Rang, dann Reihenfolge in `SEARCH_KINDS`, dann `at` neueste zuerst, dann Titel (`localeCompare` „de“)
  - `markOf(title: string, text: string): { before: string; match: string; after: string } | null` – nur wörtlich, Groß und klein egal (Entscheidung 26)

Aussehen und Bedienung wie Entwurf SC und Spec Teil 5 „Das Fenster“: Platzhalter „Suchen …“, Filterleiste mit `aria-pressed` und Zahl, Kürzelzeile „@ Personen · # Server · / Seiten“, eine Liste mit Symbol, Titel mit `<mark>` (aus `markOf`), Ort rechts, Kontextzeile; Zeile für fehlende Quellen („Mails gerade nicht erreichbar“, Namen aus `SEARCH_LABELS`); Fußzeile „Tab Filter wechseln · Enter öffnen · Esc schließen“. Tab und Umschalt+Tab im Feld wechseln den Filter (`preventDefault`). Ein Kürzel setzt den Filter. Leeres Feld: die bisherigen Seiten (`initial`). Nur ein Kürzel: Hinweis, was sich dort suchen lässt. Eine Live-Region (`aria-live="polite"`) sagt die Zahl der Treffer. Unter 860 px Breite: volle Breite, Filterleiste waagerecht scrollbar, Kürzelzeile ausgeblendet.
