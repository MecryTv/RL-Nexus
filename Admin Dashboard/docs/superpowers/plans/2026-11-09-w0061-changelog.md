# Changelog im Admin Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine Seite Dev → Changelog im Admin Dashboard: Versionen mit Änderungen schreiben (auch aus `works changelog`), als Zeitleiste oder Liste durchsuchen und eine Version als Bild in einen wählbaren Discord-Kanal posten, aktualisieren und wieder löschen.

**Architecture:** Regeln, Typen, works-Parser und Filter liegen ohne DOM in `shared/changelog.ts` (geprüft mit `npm run check`). Der Server speichert in zwei neuen Tabellen (`server/changelog/store.ts`), zeichnet das Bild (`server/changelog/image.ts`, Helfer der DMs) und postet über das Bot-Token wie die Statusmeldung (`server/changelog/post.ts`). Die Oberfläche ist eine Dev-Seite unter `src/changelog/`, der Kanal-Dialog der Statusmeldung wird wiederverwendbar.

**Tech Stack:** Node (Type-Stripping, `erasableSyntaxOnly`), Fastify, MariaDB, `@napi-rs/canvas`, React + Vite + SCSS-Module, Discord REST v10 (Components V2).

**Spec:** `Admin Dashboard/docs/superpowers/specs/2026-11-09-changelog-design.md`

## Global Constraints

- Nur Developer: alle Routen im `developerOnly`-Block von `server/app.ts`, Seite über `devPage(...)`.
- Version Pflicht, eindeutig, Form `^\d{1,3}\.\d{1,3}\.\d{1,3}$`; Titel Pflicht, höchstens 80 Zeichen; Änderungen 1 bis 30; Text Pflicht, höchstens 200 Zeichen; Aufgabe leer oder `^W-\d{4}$`.
- Arten `neu`, `verbessert`, `behoben`, `intern` („Neu“, „Verbessert“, „Behoben“, „Intern“); Bereiche `bot`, `dashboard`, `admin`, `webseite` („Bot“, „Bot-Dashboard“, „Admin“, „Webseite“).
- Intern nie im Bild, nie im Alt-Text; eine Version nur mit internen Zeilen wird nicht gepostet.
- Bild: 900 logische Pixel breit, Ausgabe 1100 breit, höchstens 580 hoch; eine Bildzeile je Änderung, Rest „+ N weitere im Admin Dashboard“; Alt-Text höchstens 1024 Zeichen.
- Kanal in `admin_state` unter `changelog_channel`, Auswahl aus `statusChannelOptions(config)` (Server `config.guildId`).
- Jede Schreibaktion ins Protokoll: `audit(actor, "changelog.<aktion>", null, "<Version> · <Titel>")`.
- Texte Deutsch, du-Form, ohne Gedankenstriche als Stilmittel. Farben aus `src/styles/_tokens.scss` (Neu `--c-win`, Verbessert `--c-purple`, Behoben `--c-blue`, Intern grau; Bot `--c-red`, Bot-Dashboard `--c-mod-utility`, Admin `--c-purple`, Webseite `--c-blue`).
- Prüfen: `npm run check`, `npm run check:db` (nur die 2 bekannten Fehler: Kontaktformular, Tabellen ohne Bereich), `npm run typecheck`, `npx oxlint`, `npm run build`.

## Review Focus

- Die Nachricht wurde in Discord schon von Hand gelöscht: „Post aktualisieren“ postet neu, „Post löschen“ und „Version löschen“ nehmen 404 als erledigt.
- Dem Bot fehlt im Kanal ein Recht (403/50013): Satz mit dem Grund, die Version bleibt Entwurf, nichts halb gespeichert.
- Eine Version nur mit internen Zeilen: Knopf aus mit Satz, die Route lehnt mit 409 ab.
- Sehr viele oder sehr lange Zeilen: Das Bild bleibt ≤ 1100 × 580, endet mit „+ N weitere …“, der Alt-Text ≤ 1024.
- Zwei Versionen mit derselben Nummer (auch beim Umbenennen): 409 „Die Version 1.4.0 gibt es schon.“
